# 清透玻璃组件标准与正式界面验收

基准：8631 原型的清透方案。实施对象：8630 的真实工作台、配置管理、运行记录、设置及其浮层。最近整体复核：2026-09-27；浅色层次与动效更新：2026-09-29。

2026-10-06 按当前源码候选同步材质、紧凑工作台与 tab 反馈标准；本次同步不是新增浏览器验收结果。设计取舍及待验证边界见 [Liquid Glass 实施说明草稿](../../ui-review/2026-10-06/liquid-glass-implementation.md)，原有验收记录保持其原始日期与范围。

这份标准以组件角色验收，而不是要求业务界面逐像素复制演示原型。正式页面继续使用真实 schema、配置模型和运行流程；同一组件在不同页面使用同一材质、文字和状态。一套玻璃设计提供浅色/深色两种模式，通过共享 tokens 切换，不维护独立皮肤。

可点击的验收基准现位于 [`/static/design-system.html`](http://127.0.0.1:8630/static/design-system.html)，复用正式组件源码和主题；固定状态、操作步骤与参考来源见 [交互样板说明](live-reference.md)。下面的文字用于解释样板，不能代替交互和目标平台实测。

## 基础标准

| 可读性 | 固定表头使用当前模式的稳定实色底；浮层不能透出干扰文字；不以全透明为目标 | `--table-head`、`--glass-dialog/picker` |

## 组件验收矩阵

每项至少检查默认、鼠标悬停、键盘焦点；有相应状态时再检查选中、展开、禁用、错误、加载、空内容。不可用状态不能只改变外观而仍可执行。

字体按内容角色区分：表名、生成样例与操作说明属于 UI；字段标识、SQL/YAML、代码、路径和版本属于技术文本。数字对齐使用 `tabular-nums`，不为对齐把整段自然语言改为等宽字体。新增组件直接复用这些角色和主题变量，不为单页再加一套字体或皮肤。

引擎格式示例中的示例值继承 UI 字体；组件执行日志使用 `--mono` 与统一说明字号、行距，不依赖浏览器默认 `pre` 字体。关系检查区的表名、字段数量、查看按钮保留明确间距，展开模式与长表名允许换行。规则抽屉中的复选框保持 grid 布局，避免局部 display 覆盖使已选勾号消失。

关系图选中表或连线仅触发一次 120ms 装饰轮廓淡出；最终选中状态立即显示，节点、连线与箭头不移动。初载、恢复、悬停和重复选择不播放，减少动态效果时禁用。依据 [Carbon 动效原则](https://carbondesignsystem.com/elements/motion/overview/)与 [Fluent 动效原则](https://fluent2.microsoft.design/motion)，反馈集中在当前操作对象，不增加持续流动来暗示生成进度。

## 可访问性与兼容边界

- 输入与操作按钮共用轻微凸起的表面；输入保留标签、文本光标和独立焦点，切换按钮的已选态使用浅色内凹表面。分段选择的当前项使用浅槽中的凸起表面。折叠标题静态有浅底、常驻箭头；样板另显示“展开／收起”，仍使用原生 details/summary。
- 按钮文字和图标、选择控件形状及标记、输入标签及可辨表面分别承担识别职责。阴影是补充线索，保留键盘焦点、错误提示及高对比度系统轮廓；柔边方案仍需在目标显示环境核验，不能宣称整站对比度已通过。原则来源：[Fluent Elevation](https://fluent2.microsoft.design/elevation)、[W3C 非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

- 不隐藏焦点轮廓、不用模糊字体制造柔和感。中英文 UI 的圆角来自本地字体轮廓，代码等宽字体保持原样；字体文件随静态资源分发并保留 SIL OFL 1.1 许可证，缺字沿既有字体栈回退。可空/唯一复选框沿用原生 input 与 label；视觉布局不改变可访问名称。
- 鼠标悬停的柔阴影不替代键盘焦点。下拉保持 `.active` 与 `.selected`/`aria-selected` 分离；普通模式的上下按钮位于选项区之外，只在溢出时出现，不遮住选项，不依赖悬停定时器。键盘仍从触发器浏览与提交；高对比度下以系统颜色的轮廓和勾号表达状态，并恢复原生滚动条，不能仅依赖阴影。
- 弹窗加载反馈不增删背景页面高度；慢响应中取消、失败和关闭后的焦点也要验收。状态时间用于记录页，AI 连接提示只保留本次结果及修复方向；修改输入后使旧结果失效。
- 浮层打开后入口被禁用或移除，不能继续提交旧值；宿主隐藏分区时主动关闭所属浮层，不提交、不抢夺其他控件焦点。正常关闭时焦点回到可用入口，保留当前滚动位置。
- 外观偏好以最新持久化值为准，迟到的跨标签事件不能回滚新的选择；存储不可读时仍可接收事件中的合法偏好。外观切换不重建业务草稿。
- `prefers-reduced-transparency` 提供实色阅读层与浮层；无 backdrop-filter 支持时使用实色；`forced-colors` 恢复原生选择控件。减少动态效果时去掉新加的过渡。
- 44px 是本项目相应 Web 触控控件的 CSS 命中区标准，不是所有控件已完成触控验收的声明，也不等于 visionOS 的空间输入尺寸。XR 客户端与平台输入适配未在本次交付范围内。
- Windows 浏览器验证不能代替 macOS/Linux 的字体渲染和 Safari/Firefox 验收。未执行的平台与真实 AI 调用/数据库写入不得标记通过。

## 本轮验收证据

弹窗退出遵循单一显式入口：只读窗口使用顶部关闭；编辑和确认使用底部取消/返回与提交。参考 [Fluent 2 Dialog](https://fluent2.microsoft.design/components/web/react/core/dialog/usage) 的关闭入口建议与 [WAI-ARIA Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 的焦点和键盘约束。去掉重复 × 不改变 Esc、取消草稿、在途结果失效与焦点恢复；无头部按钮时先聚焦标题，Tab / Shift+Tab 分别进入首尾控件。

浏览器检查与测试结果在实施完成后记录于 `implementation.md`；正式入口到共享模块的完整对应与本次迁移证据见 [正式组件迁移核对](production-migration.md)。自动 DOM 测试不能代替实际视觉检查。对尺寸、状态、字体的结论以正式页面计算样式及实际交互为依据。
