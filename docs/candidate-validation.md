# 候选版本验收

候选分支：`codex/workbench-candidate`。先通过 Pull Request 验证同一提交，再决定是否合入 `main`。候选包用于试用，不等于正式 Release，也不自动发布到 PyPI。

## 获取可追溯的安装包

打开该 PR 的 CI 工作流。`packages` 任务会构建五个 package 的 sdist 和 wheel，执行依赖一致性检查，并在完整五包、仅 Core/Web 两种独立环境中启动真实 Web worker、验证页面和数据生成。成功后上传 `sqlseed-candidate-<commit SHA>`，保留 14 天。

下载时核对产物名称、PR 当前提交及 CI 所属提交。五个 wheel 应来自同一个产物；在新建的 Python 环境中一起安装，避免混用开发版与软件源中的旧插件。保留这组包和提交 SHA，反馈问题时同时提供 Python、操作系统、数据库版本及最小复现步骤。

## 实际试用范围

使用新建测试数据库或可丢弃的副本，依次验证：

1. 仅 Core/Web 启动：手动规则、预览、生成、保存配置及运行记录可用，缺失 AI 等扩展有明确提示。
2. 完整五包：AI 配置状态与实际连通性分别验证；真实模型的建议质量单独记录，不能用固定响应测试代替。
3. SQLite 与 PostgreSQL：连接、结构读取、父子表生成、数据库约束、分页读取及失败后的实际提交量。
4. 支持环境中的组件变更：卸载后对应功能提示不可用，设置和草稿保留；重新安装后恢复。Windows、系统 Python 或外部托管环境不支持页面内改包。
5. 服务器 Python：普通运行不要求本机 virtualenv；外部部署需提供认证与访问控制，页面不能选择任意远端解释器。详见[Web 工作台](web-workbench.md)。

## 合并条件与当前限制

- 同一候选提交的 lint、类型、架构、文档、前端、Linux Python 矩阵、macOS/Windows、真实 PostgreSQL 和安装包 CI 均应通过。
- 本地完整离线验证明确排除依赖真实 LLM 的用例；远程未配置模型时的跳过也不代表模型质量已验收。
- 项目要求本地 mutation 门禁通过。目前最近一次完整结果仍为 222 项、179 killed、41 survived、2 suspicious，退出码 10。随后补充的容量契约测试已使两项慢失败变异快速被检出，但尚未重跑完整 mutation，不能把它报告为 gate 通过。
- 41 项幸存复核涉及诊断文本、等效分支及合法采样差异；不通过断言无关日志、锁死采样常数或放宽门禁来制造通过结果。该门禁结论未处理前，PR 保持 Draft，不自动合并。
- PostgreSQL 当前不支持 Web 清空后生成、复合外键和跨 schema 外键；Web 尚无多用户认证。完整支持边界见[支持与维护约定](maintainable-release.md)。

已发现的阻断问题在候选分支修复并重新验证；普通体验优化可以在后续版本迭代。每次修改源码后，使用新提交的 CI 和安装包验证，不混用之前的通过记录。
