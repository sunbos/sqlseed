# 评审问题落实方案

用户已授权依据阶段一评审采取最佳实践并进入下一流程。本轮依次完成实现、针对性回归、真实浏览器走查及独立设计归档；不覆盖 [阶段一现状](../../design-review/2026-09-08/README.md)。

## 方案选择

采用对象范围不变的局部改进：保留工作台／配置管理／运行记录和当前表三个视图，调整信息密度、阅读入口与反馈顺序。仅改间距不能解决图阅读和错误发现；整页重建会重新引入已经解决的范围和生命周期问题，故不采用。

## 具体设计

| 问题 | 本轮设计 | 验收 |
| --- | --- | --- |
| R1 长表名拥挤 | 桌面侧栏适度加宽。每项固定勾选和图入口，表名与状态分两行；表名允许换行且可取得全名。搜索只过滤浏览。 | `purchase_order_items` 等名称与图标不重叠；选表、勾选、查看依赖三种操作不混淆。 |
| R2 图难读 | 常显总览说明，提供“阅读当前表依赖”；缩放百分比反映实际渲染比例，另有“适应画布”和“100%阅读”。搜索结果可直接定位真实完整依赖。 | 24 表可总览；指定表以自然尺寸居中可读；不改变生成勾选，复合 FK、方向和 IME 保持。 |
| R3 顶部占用 | 标题／保存状态／全局操作一行；配置工具与当前引擎、地区合并为紧凑上下文栏。去除重复流程提示，保留就近规则说明与全局设置对话框。 | 在 1144×872 首屏中工作台起点较基线前移；名称、引擎、地区、保存和生成入口仍直接可见；窄屏不溢出。 |
| R4 路径身份 | 用临时 SQLite 复现后，共用精确的物理目标规范化。普通路径旧 key 保持；旧 URI hash 可能对应另一真实文件，不能自动接受；采用严格 canonical key，旧 URI 配置须导出后明确导入，固定运行快照不改。 | 普通路径与等价 URI 归属一致；不同库和私有内存仍隔离；旧配置兼容不依赖 schema 相同或路径猜测。 |
| R5 AI 字段授权 | 单入口不变；指定字段增加表／列／全名搜索、已选总数、选择筛选结果及清空选择。保护字段单独展示只读原因。 | 搜索不丢隐藏选择；只授权 `orders.promised_at` 时请求精确匹配，生成范围不变；忙碌与过期保护保持。 |
| R6 阻断项靠后 | 依赖检查首先给出范围状态、阻断与提醒计数，阻断卡片先于提醒；来源明细按需展开，生成顺序另列。失败时禁用检查窗口的生成入口。 | 38 条来源下首屏可见阻断原因和定位动作；展开仍有完整映射；局部与未选表不冒充全局通过。 |

## 依据与应用边界

- [Carbon Data Table](https://carbondesignsystem.com/components/data-table/usage/)：操作靠近其作用对象，表工具与批量操作分开；不引入 Carbon 组件依赖或替换现有主题。
- [W3C APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)：保持角色关联、焦点移动和手动激活。
- [NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)：常用信息直接可见，低频明细按需展开；不把引擎／地区藏入无意义的“高级”入口。
- [W3C Error Identification](https://www.w3.org/WAI/WCAG22/Understanding/error-identification.html)：用文本指出问题及所属对象。错误优先排序是本产品设计决策，不宣称规范规定了唯一布局。

以上是设计依据，不构成 WCAG 全面符合性认证。AI 模型语义、通用业务对账及 PostgreSQL 全流程仍需独立验收。
