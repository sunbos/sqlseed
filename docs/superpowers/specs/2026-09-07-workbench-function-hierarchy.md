# 工作台功能层级与精细化方案

日期：2026-09-07。依据：用户本轮 7 条浏览器批注与 6 项问题，以及当前实现、生成器实测和官方数据库语义。本文区分已经修复的缺陷、当前能力、建议新增的产品能力；不是已交付功能清单。

**后续状态（同日）：** 用户随后要求按权威标准实施。下文“建议／待实现／当前”保留提案时点的事实；配置管理、三项导航、预览入口收敛、字段分工、统一日期、AI 范围与关系建议及 SQLite 清空事务已实施，具体交付与环境边界以 [标准化实施记录](../plans/2026-09-07-workbench-standards-implementation.md) 为准。PostgreSQL 清空仍未开放。

## 结论

当前问题集中在三个方面：生成器存在真实契约缺陷；同一页面并列展示了不同对象层级的动作；高级能力缺少受约束且可理解的入口。保留 v8 的视觉语言，重新按对象和任务组织功能。

主方案为 **工作台 / 配置管理 / 运行记录**。数据库连接仍是全局上下文入口。完整能力矩阵见 [功能与生命周期审计](../plans/2026-09-07-web-capability-lifecycle-audit.md)。

## 1. 主导航及基础／高级层级

| 入口 | 默认可见的主要任务 | 按需展开的能力 |
| --- | --- | --- |
| 工作台 | 选择表、设置数量、字段规则、当前配置引擎/语言、查看样例、生成数据 | 关系图细化、约束与派生、原生方法、配置文档 |
| 配置管理（建议新增） | 新建、查找、打开、复制、重命名、删除 | YAML/JSON 导入导出、按数据库筛选 |
| 运行记录 | 结果、计划／提交数量、错误、历史定位 | 快照、从快照新建、筛选与保留管理 |
| 当前数据库入口 | 连接、切换、断开、连接事实 | 重新读取表结构、结构 JSON 导入导出 |
| AI 辅助 | 分析范围、业务说明、规则建议审阅 | AI 服务设置、关系建议及其依赖解释 |

另外比较过两种方向：

- 保持当前两导航、继续加弹窗：改动小，但配置生命周期仍难发现，不能解决本次反馈。
- “生成配置 / 运行记录”，把工作台作为配置详情：对象结构更紧凑，但需要更明显的返回与新建路径。

优先推荐三个入口，因为它保留用户熟悉的工作台，又给配置管理明确位置。没有充分理由把每个工具都升为一级导航，也不应重新启用历史旧页面。

采用基础优先、高级按需展开，而非删除高级功能。高级入口需要明确名称，避免层层嵌套。依据：[NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)。

## 2. 首屏纵向空间与动作作用范围

- 当前工作区上方的数据库工具条重复显示库名，且把字段表继续向下推。库名和连接事实保留在侧栏；结构动作收进该库的“结构工具”菜单。在整库关系视图中，可以显示相关工具条；字段编辑视图不常驻整条。
- 全局引擎／语言保持可见，但收紧为有明确文字标签的配置摘要行；点击修改，不回退到难发现的小图标。
- 去掉常驻的“点击上方字段或规则编辑”说明和重复的底部字段区域，把空间让给字段与样例。
- 结构导入／导出补齐与当前图标体系一致的图标。图标辅助识别，不替代文字。

## 3. 字段和取值规则分工

| 点击位置 | 目标内容 |
| --- | --- |
| 字段名 | 字段信息：类型、主键、可空、默认值、CHECK、外键列映射、引用关系 |
| 取值规则 | 生成规则：生成器、参数、派生、NULL 比例等可编辑配置 |

两者可复用同一右侧面板的“字段信息 / 生成规则”分页，分别打开对应页。字段信息默认只读，不暗示能够修改数据库 schema。取值规则仍是直接编辑，不再要求先点字段再点“调整规则”。

这是本轮建议，当前正式页面仍为两处都打开规则抽屉；不把已有行为误报为新的分工。

## 4. 三种“刷新／预览”的真实区别及收敛方案

| 当前动作 | 实际读取与计算 | 数据库写入 |
| --- | --- | --- |
| 预览本表 | 计算当前表的少量样例，以及其执行所需的已选上游 | 无 |
| 预览所选表 | 为勾选生成的表计算少量样例 | 无 |
| 刷新结构 | 重新读取数据库的表、列、约束和关系，处理与现有配置的冲突 | 无；也不生成样例 |

建议把前两个收敛成 **“查看样例”+范围选择（当前表／已选表）**，默认当前表，保留对比整份配置的能力。不要在上下两个位置同时放同级按钮。

“刷新结构”改为 **“重新读取表结构”**，放数据库结构工具中，适用于数据库表结构在外部变化之后。生成数据前的检查仍由主流程自动完成；需要排查时也能主动打开检查结果。

## 5. 生成前清空与 ID 重置

建议在生成策略中提供：

1. **追加数据（默认）**：保留现有数据，数据库继续分配自增键。
2. **清空指定表后生成（待实现）**：先显示清空影响计划，再执行用户明确选择的替换。

“清空”与“重置自增序列”是独立概念。支持自增的列可提供“重置为序列起点”，显示具体起点（常见为 1）；UUID、文本或复合主键没有通用“从 1 开始”。编号模板的 sequence 则属于生成规则，不能与数据库 identity 混为一谈。

SQLite 普通 INTEGER PRIMARY KEY 空表通常从 1 开始，显式 AUTOINCREMENT 还保留历史序号；PostgreSQL 清空是否重置 owned sequence 有独立选项。参考：[SQLite Autoincrement](https://www.sqlite.org/autoinc.html)、[PostgreSQL TRUNCATE](https://www.postgresql.org/docs/current/sql-truncate.html)。

必须先实现的执行边界：

- 清空影响范围独立于生成上游依赖。要检查被清空表的全部下游、跨 namespace 引用及可能的 CASCADE/SET NULL，不自动清空未选表。
- 清空阶段按子表优先，生成阶段按父表优先；不能以关闭 FK 绕过检查。
- 摘要明确显示将清空的表、已有行数、待生成数量和序列行为。
- 如果承诺“生成失败保留旧数据”，删除和写入必须具备可验证的整体事务／恢复机制。当前逐表批量提交不具备这个承诺。
- PostgreSQL 现有 reset 查询存在跨表 sequence 定位缺陷，需修复并真实 PG 验证后开放；本轮未把现有 primitive 接成可用按钮。

本轮修复了 SQLite 首次连接漏启用外键的问题；**正式工作台仍仅支持追加，清空／重置不是已实现功能**。

## 6. 配置删除与保留策略

当前没有配置删除路由或 store 方法。建议在配置管理页支持删除整份配置，保留已运行快照和运行记录，不影响业务数据库。

后端用 expected revision 原子删除，处理并发修改／执行建档；删除当前编辑配置后清除旧 id/revision，避免继续向不存在的配置保存。运行快照是独立数据，删除配置不能连带删除历史执行证据。

每份配置保存更新 revision，并非每次保存都必须新增一份独立配置。另存、复制、从运行快照新建则应产生新配置。完整新建／复用／删除流程优于只补一个藏在弹窗里的删除按钮。

## 7. AI 分析范围与字段关系

当前已支持“当前表 / 已勾选生成表”；未支持独立整库、任意表多选、指定列多选；返回建议限于 generator/params。模型虽然看得到同表字段，但当前协议不允许应用派生关系。

建议 AI 有独立范围：**整库 / 指定表 / 指定列**，不与生成勾选联动。

- 分析上下文与允许修改范围分开：选一个字段，也可以读取其整表及必要上游；仅返回并允许修改所选目标字段。
- 未勾选表的建议进入已有 tableDrafts，不自动加入生成。
- 增加业务描述，例如“姓名为中文全名，邮箱使用姓名拼音”；不只凭字段名猜测。
- 同表关系以受约束模板提出，例如姓名拼接、数量×单价、固定日期偏移。模型返回关系类型与参数，由服务端转换成现有派生能力。
- 关联修改成组审阅、原子应用；显示来源→目标、原因和同一行样例。应用前检查类型、NULL、约束、完整列依赖图及循环，不能仅验证单条建议。
- 保留手工高级派生／原生规则入口。AI 不输出任意 Python/SQL 或无限制表达式，也不能默默改变用户未选择的列。
- 整库按表和必要依赖分批，不能无限塞入上下文再截断。

增加 AI 不是生成器缺陷的补救方式。引擎契约和 locale 问题应先在确定性生成层修复。

## 8. 控件统一与已复现问题

### 下拉裁切：本轮已修复

实页测得选项 bottom 784.9，而 modal-body bottom 593.2 且 overflow:auto；绝对定位列表被父容器裁掉。共享下拉组件展开时改挂当前 overlay 并固定定位，按视口空间上下展开、限制宽高；选择／关闭恢复原位置，清理 scroll/resize/focus 监听，Escape 先关选项而非关闭整个编辑器。

新增真实模块回归；浏览器独立验证页成功展开并选择末尾 Italiano，取消临时设置。原用户页面有未保存草稿，未被刷新或覆盖。

### 日期样式：待统一组件

当前使用原生 input[type=date]，打开后的日历由浏览器／系统绘制，页面 CSS 不能稳定统一其内部样式。建议使用同主题日期选择组件，保留 YYYY-MM-DD 直接输入、月年选择、今天／清空、键盘导航与校验；日期和 datetime 共用组件。不能只替换图标就声称修复弹出日历风格。交互与键盘依据：[WAI-ARIA Date Picker Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/)。
