# 网页内组件管理与单一字段编辑路径

用户明确要求修正命令行维护流程及预览重复操作条。本设计沿用已批准的安装/卸载能力与列名、规则独立入口，替代上一轮要求终端切换维护模式的普通用户流程。

## 交互依据与决定

Carbon 的[表格规范](https://carbondesignsystem.com/components/data-table/usage/)区分独立点击目标、整表工具栏和批量选择后的操作。结合 sqlseed 的使用场景，本轮采用“直接操作字段 → 同一个字段面板”：移除单列选择后新增的上方工具条；保留整格悬停提示及列名、规则两处独立点击目标。AI 调整属于当前字段规则上下文，放在取值规则面板中。

Carbon 的[编辑模式](https://v10.carbondesignsystem.com/community/patterns/edit-pattern/)为复杂字段编辑提供侧面板方案。本项目保留已有面板与配置模型；不会为入口收敛另建第二套编辑状态。未应用或无效的规则草稿不能被 AI 跳转静默丢弃。

[JupyterLab 扩展管理](https://jupyterlab.readthedocs.io/en/stable/user/extensions.html)提供网页中的安装和卸载操作，即使底层使用 pip，也无需将日常用户流程写成终端教程。该先例不意味着 Python 插件可以安全热卸载；本项目由服务自动完成隔离和恢复。

## 用户流程

1. 设置页每个可选组件显示当前可执行的安装/卸载按钮。必需组件没有移除入口；存在反向依赖时给出具体原因。
2. 点击后展示操作对象与影响；解释器、发行包等信息折叠在技术信息中。确认只提交一次。
3. 有正在运行的生成、AI 或数据库操作时，拒绝开始并显示原因，用户完成工作后可重试。不存在强制停止按钮。
4. 空闲时自动暂停业务，依次显示准备、处理组件、恢复服务。页面与配置草稿保持，服务替换期间自动重新连接，不要求浏览器重启或手工刷新。
5. 完成后刷新组件可用状态；失败显示真实原因。恢复失败提供“重试恢复服务”，不会重新安装或卸载一次。

## 后端实现

- 默认 `sqlseed-web`/模块入口启动 supervisor，持有环境独占锁、监听 socket 和管理状态；业务与维护 worker 继承 socket。既有普通 ASGI 路由及 NDJSON 流继续由 worker 提供，不引入全量 HTTP 代理。
- 父进程管理白名单操作、计划、包安装器及状态，只在旧业务 worker 安全退出后改包，新业务 worker 恢复后才发布任务终态。
- worker 全部非管理 HTTP 请求和实际后台线程受统一 RuntimeGate 统计。锁内判定空闲并暂停准入，避免检查完成后又启动业务的竞态；线程 lease 保留到实际退出。
- 连接参数、同一 conn_id 与 AI 会话覆盖通过私有 IPC 和父进程内存往返，不写入文件。SQLite 内存库无法靠重连保留，存在此类连接时明确阻止操作。连接恢复失败逐项说明，不静默更换生成引擎。
- 同源、本机、随机 token、环境白名单、冻结版本、反向依赖、超时与输出脱敏保护沿用。默认受管模式执行后自动恢复；legacy 手动维护入口仅兼容，不作为网页用户主流程。
- 自行托管 `create_app()` 的部署不能被假定为可自管重启，返回能力不可用；普通页面只说明由应用管理员管理，命令放在折叠的管理员排查信息中。

## 状态契约

管理状态增加 `automatic_lifecycle`、`phase`、`instance_id`、`service_generation`；`enabled` 仅表示管理权限，不能据此锁定正常 AI 设置。阶段为 ready/busy/preparing/installing/restoring/recovery_failed。

任务保留 running/succeeded/failed，增加 stage/service_ready；GET 可以重试，execute 不自动重试。换 worker 造成的短暂断连显示重新连接；限时未恢复后保留只读状态刷新。`POST /recover` 只重试服务恢复。

## 验证

分别验证直接字段入口、AI/设置往返、预览高度与焦点，以及安装计划、单次提交、忙碌拒绝、短暂断连、真实子进程轮换、同 ID 连接恢复、后台线程 lease。真实安装器仅运行于临时 virtualenv；用户当前环境不执行包变更。浏览器验证普通入口中无命令行步骤，包操作后无需页面重载。

## 卸载后的功能反馈（用户后续请求）

- 卸载确认先说明影响；完成后组件行与受影响功能入口继续提供具体说明，不能只靠一次性成功通知。
- AI 缺失时说明规则建议与分析不可用，提供插件安装入口；保留手动配置和已有服务设置。已安装却导入失败使用加载异常提示和排查入口，不误称未安装。
- Mimesis 缺失时说明当前配置无法预览/生成；明确重新安装或主动切换可用引擎。列级覆盖须定位相关字段，不静默改动 provider、规则或生成勾选。
- CLI 与 MCP 的提示限定各自终端命令、客户端调用，不暗示网页核心功能依赖它们。
- 可选组件的 Web 可用性要求发行包 metadata 存在且模块可加载；卸载后残留的内存模块或 editable 路径不能证明该组件仍已安装。
- 服务恢复后即使存在未保存的 AI 草稿也刷新组件可用性，保留草稿并禁用不可执行操作；重新安装后恢复操作能力。DEFAULT 预检缺插件的错误必须有恢复入口，不能绕过字段保护进入分析。
