# 三表 AI 分析修复与进度反馈

**目标：** `order_items / orders / users` 在当前 Base 配置下联合分析，返回可审阅且经过真实只读校验的建议；等待和失败都有可理解的反馈。

**范围：** 保持当前 AI 助手及审阅后应用流程；本轮不写入演示数据库、不更换数据生成引擎，不提交此前与本轮的未提交修改。

## 已确认的问题

- 2026-09-09 真实模型调用约 11 秒返回 13 条建议，其中 `orders.order_no` 为 `pattern: ORD-#####`。实现采用正则表达式，`#` 是普通字符，结果恒定；UNIQUE 校验随后进入多层重试。
- 同一次模型回复为 Base 的 `phone` 指定 mask。Base 接受但忽略 mask，不能满足该演示库的 11 位长度约束。发送给模型的目录只有简短方法摘要，缺少这个引擎差异。
- 样例校验沿用写入流的宽重试预算；失败时服务端丢弃检查 issues，前端仅显示笼统失败，无法分辨模型等待和候选校验。
- 页面还可能保留 Web 服务重启前的 conn_id，此时返回 unknown connection；必须提示重新连接，不能将其解释为模型故障。

## 实施方案

- [x] 后端仅在真实阶段边界发布 `context / model / validation / preview` 事件，最终返回结果或安全错误。保留 `/suggest` 的 JSON 兼容，用 Accept 请求 NDJSON；不创建持久任务，也不展示虚构 token/百分比进度。
- [x] 对同一连接的 AI 请求设置独立门禁；模型网络期间释放数据库操作锁。取消跳过后续工作，旧 worker 真正结束后才释放门禁。180 秒为界面等待预算，不能承诺能中断外部模型服务。
- [x] 对 AI 只读校验配置每流尝试预算和合作式取消。普通 core 生成默认行为不变；异常包含表、列、生成器或具体 CHECK 信息。
- [x] 补齐 AI 上下文中的正则、模板和当前引擎能力说明；拒绝空正则及无效参数，不静默改写用户配置。
- [x] 前端显示真实阶段、已耗时、校验问题和被拒绝原因；关闭、切换配置、超时后的晚响应不可复活建议。建议继续默认不勾选。
