# 预览数据与配置编辑入口细化

## 本轮问题与设计

用户仍不清楚“查看样例”的用途和“最多 3 条”的依据；“高级配置”折叠展开后只有一个配置文档入口。

原先前端 `count:3` 与字段表三列样例绑定，后端实际已接受每表 1–100 行。3 不是标准或生成能力限制。仅增加顶部说明仍没有让结果容易找到，因此将顶部改为单一“预览数据”按钮，立即打开结果窗口并自动预览。范围、每表数量放在结果窗口，默认 10，可设 1–100；按表切换、每行一条记录。工作台字段旁的前 3 条仍用于快速对照，并明确指向完整预览。

“编辑 YAML/JSON”以弱化按钮直接打开配置编辑器；单项折叠删除。编辑器保留应用、取消、文件读取和导出。字段原生方法等真正的高级参数继续折叠。

## 实现边界

- 新增 `workbench/preview.js`，预览范围和数量独立于生成配置；`session.check(preview,count)` / `previewTable(table,count)` 兼容原默认 3，正式预览窗口明确传 10。
- 每表返回 `min(预览数量, 正式生成数量)` 条，按真实结果长度显示。保留未返回结果的表与具体问题；自增、默认值、计算列按结构和当前规则解释，不能虚构 ID。
- 临时预览不写数据库，正式生成重新取值。关闭后迟到结果不能重开窗口；已选表与当前表的请求版本仍共用，已发请求仍受前后端防重保护。
- 表头保持固定，数据纵向滚动；窄窗口只在结果表内横向滚动，保留字段值的阅读宽度。

## 验证

- Web Node：383 passed；新组件专项 14 项，session 数量与异步回归新增 10 项。既有回归按新的模态交互迁移，保留草稿、防重、迟到和关系图状态断言。
- Web Python：248 passed。后端接口未修改，额外以临时 SQLite 核验 1/100、生成数截断、空父表三种情况、0/101 拒绝，以及预览后仍 0 行。
- 独立复查相关 Node 102 项通过，未发现新增确定功能问题。
- 真实浏览器默认展示 employees 10 行；切已选表并设 20，employees/order_items 各展示 20 行；设 101 显示输入错误；设 100 时 employees 实际 97 行，与配置数一致，未改变正式生成数。
- 直接打开 YAML/JSON，将文本改为另一份配置后取消，当前配置仍为已保存 v3、Base/en_US、employees 97、order_items 100。
- 760px 页面 scrollWidth=745，无页面横向溢出；数据表使用内部横向滚动，记录行高约 39px。验收结束恢复默认窗口尺寸。
- 架构/文档回归、文档标记检查、JS 语法与 diff 检查，以及 Web wheel 构建通过；wheel 包含新的 preview.js。
- 用户数据库 SHA-256 与本轮开始一致；没有创建运行或修改已保存配置。

这是两项交互细化；默认 10 是产品选择，1–100 是当前预览 API 的请求边界，不宣称来自外部标准。
