# 表头入口与插件管理续作

用户已批准继续上一阶段，并要求整格悬停提示、列名与属性分别显示下划线和打开对应编辑入口。

## 表头

- 以继续调整生成规则为范围，列名打开字段信息，规则属性打开取值规则。数据库类型、PK/FK、NULL 等事实独立展示，避免把生成规则编辑误说成数据库 DDL。
- 表头容器负责悬停底色；两个兄弟 button 各自负责 hover/focus 下划线，空白区域不触发面板。
- 共用已有字段抽屉，保留样例、表、列、行数、滚动位置和生成勾选；返回时恢复至原入口。AI 仍使用已选字段操作入口，数据库分配/外键等规则保护不变。
- 先添加直接动作、忙碌/离页、返回焦点与规则快照回归，再实施并做真实浏览器检查。

## 插件管理

- 采用启动时显式开启的独立维护模式，默认业务模式不执行安装卸载。维护模式拒绝业务请求，避免已有后台工作和被修改的包同时运行。
- 固定当前解释器、可选组件白名单、环境检查、卸载反向依赖保护、计划与确认、互斥任务、有界进度及真实错误结果。安装冻结已有发行包版本，不自动升级核心环境。
- 默认业务页提供维护模式入口说明；维护页提供实际允许的安装/卸载动作。Core/Web/Faker/Base 不开放卸载。完成后提示重新启动服务，不把当前进程模块缓存当成新安装状态。
- 后端与前端分别实施后统一真实环境边界测试。用户当前服务和环境不执行实际包变更；使用隔离测试及子进程边界验证。

具体管理设计由本轮专用设计文档补充。无需因技能流程重复请求已获得的实施授权；没有提交或推送要求。
